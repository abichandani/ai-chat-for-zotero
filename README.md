# AI Chat for Zotero

A minimal Zotero plugin (tested on Zotero 9.0.6, 64-bit) that puts an AI
chat assistant next to what you're reading. You bring your own API key —
the plugin talks to the provider's API directly, with no server in
between.

**Providers:** Claude (Anthropic) ships today. Everything
provider-specific lives in a single `PROVIDERS` registry in
`addon/bootstrap.js`, so OpenAI, Gemini, and OpenAI-compatible endpoints
are an entry away rather than a rewrite.

It adds three things:

1. **Chat button in the PDF reader toolbar** — opens a docked chat
   sidebar seeded with the open paper's full text, so you can ask
   questions about what you're reading.
2. **"Explain with AI" on text selection** — select text in a PDF,
   a popup offers an inline explanation.
3. **Tools → AI Chat: Ask About My Library** — opens the same sidebar for
   a library-wide chat. If a PDF is open in the reading pane, that paper
   is used as context too; either way a quick keyword search over your
   library feeds matching titles/abstracts to the model.

## The chat sidebar

The chat lives in a persistent sidebar docked to the side of the Zotero
window (rather than a floating drawer), and the reading pane resizes
around it. Notable behaviour:

- **Drag the edge to resize**; the width is remembered between sessions.
- **Chat history** — every conversation is saved and reachable from the
  history view in the sidebar header, most recently used first (capped
  at the 50 most recent chats).
- **Titles** are generated by the model from your first message, and can
  be renamed by clicking the title in the header.
- **Markdown rendering** for replies — headings, lists, tables, rules,
  code, and inline emphasis.
- **Copy/paste** — right-click for a Cut/Copy/Paste menu; copying a
  message bubble yields the raw markdown, not the rendered text.
- The composer grows with what you type, and long pasted messages
  collapse behind a fade so they don't swamp the transcript.
- Follows Zotero's light/dark theme.

## Install

1. Get an API key from your provider. For Claude that's
   https://console.anthropic.com/settings/keys (separate from your
   claude.ai login — it's billed per use, typically a few dollars/month
   for reading-assistant-level usage).
2. Build the plugin: `npm install` then `npm run build`. This produces
   `.scaffold/build/ai-chat-for-zotero.xpi`.
3. In Zotero: **Tools → Plugins** (or **Add-ons**) → gear icon →
   **Install Plugin From File** → select that `.xpi`.
4. Restart Zotero if prompted.
5. **Tools → AI Chat: Set API Key…** and paste your key.
6. Open any PDF — you should see a chat button in the reader toolbar.

## Configuration

Prefs live under `extensions.aichat.*`, with keys and models stored per
provider so switching back and forth doesn't lose either:

| Pref | Meaning |
| --- | --- |
| `extensions.aichat.provider` | Active provider id (default `anthropic`) |
| `extensions.aichat.<provider>.apiKey` | API key, set via the Tools menu |
| `extensions.aichat.<provider>.model` | Model override; falls back to the provider's default (`claude-sonnet-4-6` for `anthropic`) |
| `extensions.aichat.chats` | Saved chat history (JSON blob) |
| `extensions.aichat.sidebarWidth` | Remembered sidebar width |

Prefs from the plugin's earlier `extensions.claudereader.*` naming are
migrated once on startup, so an existing key and chat history carry over.

## Known limitations (this is a v1 scaffold, not a polished plugin)

- **Full-text extraction now works**, using Zotero's own documented
  `attachment.attachmentText` getter — the toolbar button pulls the open
  PDF's indexed text (up to ~18k characters, truncated beyond that to
  keep API costs sane) and feeds it to the model as context. If a PDF
  hasn't been indexed yet, Zotero indexes it on first access, which may
  take a moment on a long PDF — the button shows a spinner while that
  happens. If extraction comes back empty, the sidebar falls back to
  title/abstract-only and tells you so (try Zotero's right-click →
  "Reindex Item" if that happens on a PDF that should have a text layer).
- **Library search is keyword-only**, not semantic — it uses Zotero's
  quick-search, so phrasing needs to roughly match your library's
  titles/abstracts.
- **Chat history is stored in a Zotero pref** as a single JSON blob
  (bootstrap plugins get no bundled DB), which is why it's capped at 50
  chats.
- The Tools-menu injection uses `menu_ToolsPopup`, which is standard
  across recent Zotero versions but hasn't been tested against every
  release — if the menu items don't appear, that ID is the first
  thing to check via **Help → Debug Output Logging** or the error
  console (Tools → Developer → Error Console).
- No streaming — replies appear once complete.
- Only one provider is registered so far, so there's no provider picker
  in the UI yet; the model is set through the hidden pref above.
